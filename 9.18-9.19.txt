Level 2.1 学习记录（2026-09-18 ~ 09-19）

一、这两天完成了什么
- 一次性把文件读入动态扩容字节数组，运行期所有显示和光标操作都基于内存副本，不再回读磁盘（即题目「在内存中保存文本」）。
- nano 风格软换行：长行在窗口边缘折到下一显示行，因此不需要横向滚动。
- 方向键移动光标：上下逐行、左右逐列 + 跨行；光标不出文本范围；到屏幕边缘时自动逐行滚动，保证光标始终可见。
- 空文件、文件末尾有无 \n、最后一行恰好顶满屏幕等边界全部处理。
- 用户调整窗口时按新窗口宽度重建行表再重画。
- 错误处理：所有 realloc/malloc 失败路径 endwin() + perror + return 1；无文件参数时给提示。

三、新学到的 C 语言知识
1. 指针参数也是传值 —— 为什么用 int**
函数参数里的指针是一个副本，函数内 p = 新地址 只改副本，main 里的指针看不到变化。要在函数内改掉外面的指针，得传「指针的地址」即 int**，函数内用 (*p)[i] 操作。

2. realloc 的完整纪律
- 第二个参数是新数组的总大小，不是增量（我最初一直当成增量，realloc 多少次都只有一个 int）。

3. 只能 realloc 堆地址；运算符优先级
喂给 realloc 的必须是 malloc 系列返回的堆地址，喂栈数组是未定义行为，必崩。
[] 优先级高于 *：*p[i] 被解析成 *(p[i])，要先解引用必须写 (*p)[i]——这里错过好几轮。

4. 失败返回惯例
指针类型函数失败返回 NULL，整数类型函数失败返回 -1；调用方据此判断。

5. ncurses / 其它
- 屏幕坐标从 (0,0) 起，合法下标 0 到 y_max-1，getmaxyx(win, y, x) 参数顺序是先 y 后 x（写反过一次，resize 监测失灵）。
- printw 写的是虚拟屏幕缓冲区，要 refresh() 才上屏；一帧调一次 refresh，重画前先 erase()。
- 多字节字符不能用 %c 逐字节打印，要把一个字符的若干字节当整体 %s，且字符串必须 \0 结尾——用变长数组 char str[N+1] 收尾补 \0。
- perror 前要先 endwin() 退出全屏，否则错误信息显示异常。
- feof(fp)：fread 读满缓冲区时无法区分「文件未完」和「恰好读完」，用 feof 判结尾（踩了「读满即扩容」导致文件为 1024 整数倍时白扩容、且差点少记一块长度的坑）。

四、印象最深的几个调试过程
1. 「文件最后一个字符是 \n」
现象："a\n" 会被数成两行，第二行起点偏移等于文件长度，像是个不存在的「假行」。
AI 给反例质疑这是幻影行；本人判断编辑器里 \n 后面确实是一个合法的、能停光标的空行，决定保留它，让偏移等于 len 成为合法的结尾哨兵。

2. 「本屏画了几行」≠「文档有几行」
ai提出：
bug："a\na\na\n" 在 3 行高的终端里，光标能走到第 4 行（屏外）消失。
手算发现：幻影行在 column_len >= y_max 的 break 之前被记进了 yx_len，导致 yx_len 从 3 被撑成 4，main 的 y < yx_len-1 多放行一次。
后面我把触底判断提前到 column_len++ 之后、幻影行记录之前，屏外的行不计入本屏行数。
由此固化两个量的分工：read_txt 返回全文行数（与屏幕无关），show_txt 返回本帧实际渲染行数（恒 ≤ y_max，用来夹屏幕 y）。这两个数本来就不该相等，不能用一个 yx_len 身兼两职。

3. 「末尾没有 \n 也要显示最后一行」
我陆续提出了四个方案：
第一：在读取文件完毕后，在arr末尾加\n
第二：在arr[len]的位置加一个‘\n’，然后show_txt最后加一个判断，如果ylinkx[yx_len] == 0则yx_len--
第三：我在arr[len]的位置加'\0'，然后get_width返回0，再在show_text的for循环里加一个arr[i]==\0的判断分支
前三个都被推翻，然后想出第四个方案：
在for结束之后单独判断str_index是否为0，若不为0再进行操作
成功了。
