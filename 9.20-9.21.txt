一、这两天完成了什么
- 普通字符插入：在光标处把字符写进 arr，光标右侧内容整体后移，行表与显示重建。
- Backspace（删光标前字符） ：行中删字符；行首删 \n 时把当前行合并到上一行末尾；文章开头拦截不删。
- Delete（删光标后字符） ：定位光标右侧首字符并删除，行尾无字符时无动作。
- Enter（换行） ：本质是插入一个 \n，与普通插入共用底层逻辑，按光标是否顶到屏幕边缘分「软换行推进」与「滚动」两种处理。
- 方向键跨中文移动：沿 arr 以「字符」为单位跳跃，光标不会落在一个汉字的续接字节中间（此项本阶段已实现）。
- 所有编辑操作后统一重建 row_counter / ylinkx 并重渲染；realloc 失败路径完整。
最终版已 commit 并 push 到 GitHub，ASCII 下插入/Backspace/Delete/Enter 功能全部正常。


二、核心设计与定位思路
延续 2.1 的扁平字节数组，没有为编辑新增数据结构 。

1. 定位总原则：行首锚点 + 沿 arr 跳跃
row_counter[Cur] 给出当前行首字节下标，之后用 check_type(字节) 得到该字符占几字节、用 get_width(字节) 得到屏幕列宽，逐字符往后跳，即可定位任意光标位置对应的字节下标。ASCII 与中文走同一套循环，只是步长不同（ASCII 步长 1，汉字步长 2/3/4），不需要为中文建字符表。

2. 三种编辑的定位方式

操作	                        定位目标	                        方法
插入	                        光标右侧首字节	                从行首累加宽度，Right_Location == x 时停下
Backspace（x>0）	光标左侧字符首字节	        从行首累加，Left_Location + width == x 时停下
Backspace（x==0）	上一行最后一个字符首字节	从上一行首跳，下标 + 字节数 == 当前行首 时停下
Delete	                光标右侧首字节	                同插入定位

3. 改数组的统一套路
- 定位到目标字节下标；
- 逐字节搬移（插入右移、删除左移），用变量先记下被删字符的字节数，不能在搬运中再去 check_type 已变化的 arr；
- 重建两张表，重渲染。

三、本阶段新学 / 巩固的 C 与 ncurses 知识
1. ncurses 输入：getch 返回 int【协作，机制由 AI 讲清，代码本人写】
- getch() 返回 int：特殊键 > 255（KEY_UP、Backspace=263、Delete=330 等），普通字节在 0–255。
- 因此要先拦截特殊键，再把值当字节处理；不能对特殊键返回值做强转后当中文字节。
- 终端 Enter 在 raw 模式下可能返回 13（\r）而非 10（\n） ，Backspace/Delete 的确切码以实测为准（用程序打印返回值，不靠猜）。

2. 多字节字符只有「首字节」有身份
（1/2/3/4 字节），其后的续接字节落在 0x80–0xBF，没有身份。因此定位时必须保证下标永远停在字符首字节。所以更新了check_type函数的逻辑，靠「首下标 + 该字符字节数」推进，而不是逐字节自增。

3. 换行符在 arr 里就是原始字节
arr 中的 \n 即文件里的换行；Linux 为 \n（1 字节），Windows 为 \r\n（2 字节）。代码里直接 == '\n' 判断即可覆盖 Linux 测试文件；

4. 函数内改外部状态仍靠指针
延续 2.1：要在函数里改 main 的 x 等变量，传地址（int*），函数内 *x = ...。注意 *y++ 会被解析成「移动 y 指针再解引用旧地址」，正确写法是 (*y)++，即要注意符号的优先级。

5. 巩固 realloc 纪律
失败返回 NULL 但原指针仍有效，禁止直接 *arr = realloc(...)；用临时指针 tmp 先判空再赋值。

四、印象最深的调试过程
1. Backspace 行首合并——本阶段最大的坑
- 现象一度是「按 Backspace 随机乱跳，按很多次后退回 shell、却还能敲命令」。
- 根因有两层：
	- 行首定位循环里把「下标」当「字节值」传给 check_type（如 check_type(Left_index) 而非 check_type(arr[Left_index])），返回值不可预测，下标冲出 arr，越界读写破坏了 ch/y 等变量；
	- main 里接收返回值的 if / else if / else 互斥关系写错，以及行首合并分支漏设光标 x，导致光标 x 走到 -1 等非法值，下一轮定位再次越界。
- 转折：9.20 深夜疲劳硬改，跟ai沟通，越改越乱；最后是9.21 清醒后独立重新梳理逻辑并修改代码，半小时一次改通。再次验证「脑子不清醒时不要硬写」。

2. 「崩到 shell 还能输命令」的本质【AI提示】
程序因越界崩溃，但没有走 endwin() 正常退出，终端仍停留在 raw + noecho 模式，所以表现为「画面像在编辑器里、却能敲 shell 命令且无回显」。根因是内存越界，不是 ncurses 本身的问题。

3. Delete 先访问后判空的越界【AI提示，本人修复】
原代码先用 arr[Right_index] 取宽度/字节数，之后才判断 Right_index == len，行尾时已发生一次越界读。修复为把边界判断挪到访问之前。

4. Enter 与插入共用一个函数
在写enter函数的时候突然意识到换行本质是「插入 \n」，于是在插入逻辑里对 \n 特判：写 \n、x 归零，再按是否触底决定 y++ 还是滚动。避免另写一套换行逻辑。


五、当前架构的一个可改进点
最终通过版的 Backspace 保留了多返回值（如正数宽度 / -2 / -3 / -4 等） ，由 main 读取返回值后写分支分别处理「行中删 / 行首合并且 y>0 / 行首合并且 y==0 还要改 Where_Start」。
- 已知问题：返回值承担了过多内部语义，Backspace 的处理细节泄漏到 main，分支多、容易写错（本次多个 bug 正源于此）。
- 目前打算将其作为后续优化项，将相关光标移动、数组重构等步骤封装到BackSpace中

六、待办 / 遗留问题
1、中文输入（当前主攻，方案已想清、尚未实现） ：
	- 现状：输入法提交一个汉字时 getch 连续返回 3 个字节，现代码把每个字节各自独立走一遍插入和refresh，过程中不完整的 UTF-8 序列参与定位 → 乱码。
 	- 原来的方案：一开始是打算用数组统一接收再输出，但当时认为用户输入的文本长度是不定的，以为需要动态数组。这实现起来比较困难，故在后面写代码的时候舍弃了中文实现。
	- 已定方案：后来反应过来用户输入的内容会被翻译成一个一个字节输入，所以完全可以定义一个CharInfo变量来接收并输出，即insert被调用了字符字节长度次后再调用输出。

2、大文件性能：每次交互都会重建行表，如果是大文件时间成本较高。但目前没想到更好的办法。如果用链表，文件输出效率又会变低。

3、get_width 对非 ASCII 一律返回 2，2 字节拉丁扩展（宽度应为 1）仍会误判。

4、屏幕尺寸更改后光标位置没有判定。
